Unit 2 / Technology Systems

What computers are made of, and how data moves through them

A mandatory, externally assessed unit. Like Unit 1 it has no coursework, so this page sets out what the unit covers.

Unit studied

Why this page has no coursework on it

Unit 2 is assessed by external examination. There is no assignment brief and no submitted work, and an earlier version of this page invented three tasks, a grade, three tutor comments, and a claim that I had used Windows and Linux for it. None of that was true and all of it has gone.

A filing mistake worth naming

There is a file in my portfolio called Assignment Brief/Unit 2 Assignment Brief.docx. It is not a Unit 2 brief. It is the Unit 7 Game Review brief, with the Unit 7 assessor, the Unit 7 dates and criteria numbered 7/2A to 7/2C. It is almost certainly what misled the earlier version of this page into inventing tasks for a unit that has none. It needs renaming.

Learning aims

  1. Understand how the components of technology systems work together.
  2. Understand how data flows between internal components of a computer and is processed to provide information.
  3. Understand different types of software.

What the unit covers

A: How the components of technology systems work together

  • Systems and their applications

    • A computer as a machine that processes digital data
    • A technology system as the whole collection of hardware, software, peripherals, power supplies and communication links
    • Uses across construction, finance, health, manufacturing (including CAD, CAM and robots) and retail
    • Issues: health and safety, security, environmental impact, sustainability, privacy and copyright
    • Why organisations keep developing their systems: competitive advantage, reduced costs, better performance

  • Hardware devices

    • Devices: PCs, servers, laptops, tablets, consoles and other programmable devices
    • Input: keyboard, mouse, sensors, touch screen, microphone, scanner, digital camera
    • Output: printers (inkjet, laser, impact), speakers, force feedback devices, actuators, screens, projectors, robot arms
    • Storage: solid state, optical and magnetic
    • Automated systems such as self-service checkouts and production lines
    • Data capture devices: barcode readers, magnetic strip readers, OCR, OMR and RFID
    • Choosing and justifying devices for a specific user and purpose

  • Networking and data transfer

    • LAN, WAN, PAN and mobile broadband, and what each is for
    • Common uses: resource sharing, data sharing, entertainment, communication
    • The benefits of networking, and keeping devices in a PAN in sync
    • Wireless transfer using Wi-Fi and Bluetooth
    • Cabled transfer using optical fibre, unshielded twisted pair and coaxial cable
    • The benefits and drawbacks of each

B: How data flows inside a computer

  • Internal components

    • The motherboard as the printed circuit board holding the main components
    • The CPU: arithmetic and logic unit, control unit, registers
    • Memory: RAM, ROM and flash
    • Graphics, sound and video hardware
    • Heat dispersal: fans and heat sinks
    • Buses, and how they carry data between components

  • What makes a machine feel fast

    • CPU and GPU features: clock speed, caches, multiple cores, heat and power consumption
    • Mobile devices: system-on-a-chip, CPU and GPU, battery life
    • How mobile systems differ from traditional platforms
    • Memory and storage: cache, RAM, and solid state against optical and magnetic media
    • Comparing specifications and their effect on the user's experience

  • Analogue, digital and binary

    • The difference between analogue and digital transmission
    • Why signals are converted between the two
    • How data is represented in binary: bits, bytes and word length
    • Converting whole numbers up to 10 into binary, and 8-bit binary back to base 10
    • Units of storage from bit and byte up to petabyte

C: Types of software

  • Software and programming languages

    • Software as programs directing the operation of a technology system
    • Custom-made against off-the-shelf, and the trade-offs of each
    • The hierarchy from application software down through high-level and low-level languages to machine code and hardware
    • High-level language styles: imperative, procedural, event-driven and object-orientated
    • Low-level languages: assembly and machine code

  • Programming concepts

    • Flowchart symbols: terminators, connectors, processes and decision boxes
    • Reading and completing flowcharts, including missing decisions and outcomes
    • Worked examples including currency conversions, converting marks to grades and calculating wages with overtime
    • Declaration, input, output, assignment, variables (local and global), constants, subroutines and variable scope
    • Why code needs annotating for maintenance
    • Data types: character, string, integer, real and Boolean
    • Data structures: records and simple arrays

  • Operating systems and applications

    • What an operating system does: file management, drivers, resource allocation and security
    • Utilities: disk defragmenters, firewalls and anti-virus software
    • Graphical against command-line interfaces
    • Accessibility and ease of use on desktop and mobile
    • Productivity applications and the benefits of using a suite
    • What to weigh when installing or upgrading: hardware platform, accessibility, compatibility, cost of licence and training, speed, and security features

Where this shows up in my other work

The programming concepts topic is the theory directly under Unit 12: declaration, assignment, variables, subroutines and data types are exactly what I was identifying in the two VB.NET programs, and event-driven is precisely the style both of them are written in. The specification even names currency conversions as a worked flowchart example, which is the Unit 12 project.

The flowchart I drew for Unit 12 uses this unit's symbols: terminators for start and end, a parallelogram for input and output, a diamond for the decision, and a rectangle for the process.
