Websites

Three storefronts. One is live; two are in development. Each has a constraint behind it that shaped the design.

  • ddouble — art print storefront

    A live shop front on React and the Shopify Storefront API

    Twenty routes covering a wall-art and homeware catalogue: filterable product listings, product pages with click-to-zoom galleries, a persistent cart, a wishlist, and an account area with order history, addresses and password reset. Customer accounts are handled by Firebase and the catalogue, cart and checkout by Shopify, so card details never touch the front end. About 10,500 lines across 92 source files and 39 components.

    • React 18, Vite 6, React Router
    • Shopify Storefront API
    • Firebase authentication
    • Tailwind, shadcn/ui, React Query
    • DOMPurify as the XSS boundary
    • GA4, sitemap, service worker
    • deployed on Vercel

    Visit the live site

  • ØBJECT 29 — rebrand, in development

    A full redesign of the same shop, not yet published

    A ground-up rebrand of the art-print store under a new identity. I rebuilt the visual system around a token layer, replaced every hardcoded colour with a token, and wired the design system into the linter so a regression fails the build. I split the largest page into four components without changing its rendered output, then restyled it. All fourteen routes were checked at phone width for horizontal overflow, contrast and focus rings were measured, and the five analytics events kept working through the rewrite. Total JavaScript fell from 806 KB to 795 KB. It is not live yet: the real purchase flow needs production Shopify keys, and the site still points at the old domain.

    • React 18 & Vite 6
    • design-token system
    • Tailwind & shadcn/ui
    • accessibility & reduced motion
    • GA4 events preserved
    • 14 routes verified
    • not yet deployed

  • Tessel — single-product storefront

    A Next.js shop headless, with checkout that keeps the business out of scope

    A storefront for a watch business, built on Next.js with TypeScript and a hand-written Shopify client rather than a framework. The cart runs through server actions and checkout happens on Shopify's own page, so the business never handles card data. It verifies incoming webhooks with an HMAC signature, strips GPS metadata out of every product photograph, and ships a check that fails the build while any legal business detail is still a placeholder. About 7,700 lines across 11 routes.

    • Next.js App Router, React 19, TypeScript
    • server-side Shopify client, no Hydrogen
    • HMAC-verified order webhooks
    • EXIF and GPS stripping pipeline
    • compliance check that hard-fails
    • not yet published

Systems & other work

The infrastructure and tools behind the sites, and the projects I keep for their own sake.

  • Always-on home infrastructure

    The always-on stack I run, and the tool that runs it

    My 24/7 hosting used to depend on a laptop being awake and on a scheduled task not having quietly failed. It now runs on a Raspberry Pi under Docker Compose with restart policies, health checks and pinned image versions, so it comes back by itself. In front of it sits NEXUS, a Flask and vanilla-JavaScript single-page manager I wrote that registers services, keeps them alive with a watchdog, probes each one's health, exposes Prometheus-style metrics, and can wake or shut down the other machines on my network.

    • Docker, Docker Compose, named volumes
    • Python, Flask, vanilla JS
    • systemd, health checks, keepalive
    • Prometheus /metrics endpoint
    • Wake-on-LAN and SSH power control

    Running

  • Local AI server — dual-booted desktop

    A 35B model running on eight gigabytes of VRAM

    I wanted a language model running on my own hardware, and the obvious route — running it inside Windows — failed for a reason I had to diagnose before I could go anywhere. So I dual-booted the machine to Ubuntu, and had to solve a firmware boot problem by writing to the UEFI from a privileged token because the Windows boot manager would not do it on this board. It now serves a 35B mixture-of-experts model at about 47 tokens per second. The same box also runs a local image generator, and the two cannot run at once — together they want more memory and more VRAM than the machine has — so I wrote a service that switches modes on demand, plus a Python harness that benchmarks either one headlessly.

    • Ubuntu 26.04 dual-boot, UEFI work
    • 35B MoE served locally, Q4 quantised
    • ~47 tok/s decode, ~1.5s first token
    • image generation, ~90s per image
    • systemd GPU mode-switch service
    • headless benchmark harness

  • Built for my mother's accountancy practice

    A VAT processing tool built for a real business

    My mother runs an accountancy practice and was assembling VAT returns by hand from bank statements and receipts. I built her a web application: it reads the client tree from a mounted Dropbox folder, extracts the transactions from PDF bank statements, fills in the VAT workbook and writes a report, then puts the finished files back where the practice will see them. It has a dark interface with drag-and-drop uploads, a live log, and it stages each run in its own folder so one job cannot damage another.

    • Flask web application
    • PDF text extraction, Excel output
    • rclone and a mounted Dropbox remote
    • containerised agent pipeline
    • used for real client work

  • Face research pipeline

    A consent-gated image analysis system, written from scratch

    A self-hosted pipeline that runs on my own hardware behind a private network and never sends an image anywhere. It detects faces and produces embeddings, then scores candidate matches from research providers against a confidence model that will only report a match once more than one piece of evidence agrees. The published libraries would not build on my Python version, so I reimplemented the face detector and the embedding model directly in ONNX and checked them against the originals. Roughly 4,900 lines including the test suite.

    • Python, FastAPI, Pydantic, SQLAlchemy
    • ONNX face detection and embedding
    • Alembic migrations, 15-table schema
    • async job queue, rate limiting
    • pytest suite
    • private-network only

    Built, prototype
